# Implementation Plan: Attack Graph Staging (F09)

**Branch**: `012-e2-attack-graph` | **Date**: 2026-07-06 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/012-e2-attack-graph/spec.md`

## Summary

Build `AttackGraph` in `src/aatf/attack_graph.py` — a frozen dataclass holding `entry_points: frozenset[str]` and `edges: dict[str, frozenset[str]]`, with `available_actions(completed: set[str]) -> list[str]` that returns sorted(entry_points ∪ direct-successors-of-completed). Validates all action_ids against `REGISTRY` at construction (raises `ValueError` on unknown). The module-level constant `ATTACK_GRAPH` is the canonical v1 topology covering all 15 F07 actions. No new pip dependencies.

## Data Flow

```

  └─> ATTACK_GRAPH.available_actions(completed)
        ├─ start with entry_points (always available)
        ├─ for each action_id in completed:
        │     add edges[action_id] to reachable set (or ∅ if not in edges)
        └─> return sorted(reachable)
```
