# Implementation Plan: Internal-only Docker Lab

**Branch**: `004-e1-docker-lab` | **Date**: 2026-07-02 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/004-e1-docker-lab/spec.md`

## Summary

Create a Docker Compose lab on an `internal: true` network with three Alpine stub containers
(attacker, defender, environment) and four Makefile targets (`lab-up`, `lab-down`, `lab-check`,
`lab-status`). No Python code changes. The isolation check (`make lab-check`) is a shell script
that exits non-zero if outbound internet access is detected — it is the safety gate for
constitution Principle I and runs separately from `make test`.

## Technical Context

**Primary Dependencies**: Docker Engine (host prerequisite); Docker Compose V2 plugin; `alpine:3.19` (pinned stub image)

**Scale/Scope**: 3 stub containers, 1 network; no data volume at this stage

### Key implementation details

**`lab/docker-compose.yml`** — top-level `name: aatf-lab` pins the Compose project name
(makes container names deterministic regardless of working directory). Network declared with
`internal: true` and subnet `172.28.0.0/16`. Three services (`attacker`, `defender`,
`environment`) all use `alpine:3.19`, `container_name: aatf-<role>`, `restart: no`, and an
idle `sleep infinity` command.

**`lab/scripts/check-isolation.sh`**:
1. Check `aatf-attacker` is running; exit 2 if not
2. `docker exec aatf-attacker nc -z -w 5 8.8.8.8 53`
3. Exit 0 (isolated) or 1 (breach) based on `nc` exit code

**Makefile additions**:
```makefile
COMPOSE := docker compose -f lab/docker-compose.yml

lab-up:    ## Pull images and start the isolated lab (internal-only network)
    $(COMPOSE) pull
    $(COMPOSE) up -d

lab-down:  ## Stop and remove all lab containers and the lab network
    $(COMPOSE) down --remove-orphans

lab-check: ## Verify lab has no outbound internet access (exits 1 on breach)
    @bash lab/scripts/check-isolation.sh

lab-status: ## Show current lab container states (exits 0=running, 1=stopped, 2=degraded)
    @$(COMPOSE) ps
```
